后台 只有你能进

/admin/ 完整后台（Decap）。写文章的完整字段、媒体库、预览面板。电脑上用它。 GitHub 登录
/admin/m/ 手机写作页。标题/正文/分类/标签一屏搞定，带「回车即换行」。 口令
/admin/p/ 文章管理。全部文章 + 搜索（跨标题/正文/标签）+ 分类筛选。点一条直接打开文章，点「改」去编辑。 口令
/admin/g/ 图库。上传（自动压缩）、分类、批量改分类/删除、重命名、看原图、复制路径。
改名/改分类/删除会先进待提交队列，点「提交」才一次性推到 GitHub（改十张只等一次）。 口令
/admin/logs/ 私人角落的访问日志（IP/设备/停留时长），可导出 CSV。 LOGS_TOKEN
/admin/map/ 就是这一页。 公开

后台的内部文件 不用点，知道在哪就行

public/admin/config.yml Decap 的配置：集合、字段、分类下拉、筛选按钮。加分类要改这里。
public/admin/preview.js 后台预览面板的模板（让预览长得像线上文章页）。
public/admin/decap-extras.js 给 Decap 媒体库注入「看原图 🔍」「重命名 ✎」两个按钮。Decap 没有扩展点，只能运行时挂。
workers/oauth/src/index.ts Worker 全部逻辑：OAuth 代理 + 私人角落 + 后台接口。GitHub token 只在这一侧。

公开的数据文件 前台 JS 和访客会取

/api/posts/<N>.json分页文章清单（首页「加载更多」用）
/private/posts-all.json全部文章清单（含草稿）。只有元信息，没有正文。私人角落页面取它做搜索。
/private/posts.json隐藏文章清单（凭 ticket 才该看，但文件本身是公开的 —— 只有元信息）
/uploads/categories.json图片分类索引：{"文件名": "分类"}。图库靠它分类。
为什么正文不在这些 JSON 里： 整个 dist/ 和 public/ 都是公开可下载的，正文一旦写进去就等于公开发布。 所以私有清单只放元信息；全文搜索索引存在 Cloudflare KV 里，凭 ticket 通过 Worker 取。

加一个分类要改 5 处（漏一处就会出事 —— 加「安利」时漏了第 1 处，构建直接失败、线上发不出新版）：
  • src/content.config.ts 的 CATEGORIES（权威，构建时校验）
  • public/admin/config.yml（Decap 下拉）
  • public/admin/m/app.js（手机页胶囊）
  • src/pages/archive.astro（归档页配色）
  • src/lib/posts.ts（没指定封面时按分类挑图）
npm run check:mobile 会核对前两处与 schema 是否一致。

常用命令 在仓库根目录跑

npm run dev本地开发
npm run new新建文章草稿
npm run build构建（astro + 私有清单 + 搜索索引）
npm run check:all9 项自检：schema / 搜索 / 产物 / 排序 / 预览 / 手机页 / Worker / Decap 增强
npm run deploy发布站点。会先 pull、再构建、再体检产物、最后才发。
npm run deploy:dry只跑前面几步，不真的发布
cd workers/oauth && npm run deploy发布 Worker
三条硬规矩（都流过血）：
  • 发布前必须先 pull。后台传图走的是 GitHub API，本地不会自动更新； 没 pull 就构建 + 发布，会把刚传的图从线上挤掉（发生过三次）。用 npm run deploy，别手敲 wrangler。
  • 图片永远是二进制。只能用 blob 那条路读写；当文本处理会把图变成一堆乱码（发生过一次）。
  • dist/ 和 public/ 一律当公开。任何正文只能放 KV，凭 ticket 取。
